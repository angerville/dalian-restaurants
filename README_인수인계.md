# 대련 맛집 지도 — 인수인계 문서

신임 교사를 위한 대련 맛집 자료집입니다. 이 문서는 **다음 관리자가 코드를 몰라도 운영을 이어받을 수 있게** 쓰였습니다.
작성: 정준 (2026-10). 이 문서가 현재 사이트와 다르면 사이트가 맞습니다. 고쳐 주세요.

## 1. 한눈에 보기

| 무엇 | 어디에 | 비고 |
|---|---|---|
| 공개 사이트 | GitHub Pages (`index.html`) | 로그인 없이 누구나 읽음. 검색엔진에는 안 나오게 설정(noindex) |
| 가게 정보(이름·사진·메모) | 이 저장소의 `data/restaurants.json`, `photos/` | 직접 고쳐서 올림 |
| 댓글, 새 가게 추천, 회원 | Supabase (무료 플랜) | 승인된 선생님만 쓸 수 있음 |
| 관리 화면 | `admin.html` | 관리자만 사용. 주소는 선생님들께 알리지 않음 |

- 사이트를 읽는 데는 Supabase가 필요 없습니다. Supabase가 멈춰도 가게 목록과 지도는 계속 보입니다(댓글만 안 보임).
- 글을 쓰려면 **가입 → 관리자 승인**이 필요합니다. 승인은 관리 화면에서 버튼 한 번입니다.
- 필요한 계정은 **GitHub**와 **Supabase** 두 개뿐입니다.

## 2. 관리자가 평소 하는 일

1. `admin.html`을 엽니다(사이트 주소 뒤에 `/admin.html`). 관리자 계정으로 로그인합니다.
2. **가입 승인** 탭: 새로 가입한 사람이 보입니다. 아는 선생님이면 **승인**, 모르면 **차단**합니다. 승인 전에는 읽기만 됩니다.
3. **새 가게 제안** 탭: 선생님이 추천한 가게가 사진과 함께 보입니다. 내용을 고친 뒤 **승인**하면 사이트에 "추천" 표시와 함께 나타납니다. 부적절하면 **거절**합니다.
4. **댓글** 탭: 부적절한 댓글은 **숨기기**(되돌릴 수 있음) 또는 **삭제**합니다.
5. 선생님은 자기 댓글과 자기가 추천한 가게를 스스로 고치거나 지울 수 있습니다(사이트의 "내 글"과 댓글의 "수정"). 승인 여부, 관리자 메모, 댓글 숨김은 관리자만 바꿀 수 있습니다. 이 규칙은 `supabase/schema.sql`의 "본인 글 수정·삭제" 절이며, 이미 만든 프로젝트에는 `supabase/update_edit.sql`만 실행하면 됩니다.
6. 가끔 **백업 내보내기**를 눌러 파일을 보관합니다(회원·댓글·제안이 들어 있습니다).

비밀번호를 잊은 선생님: Supabase 대시보드 → Authentication → Users에서 그 사람의 비밀번호를 새로 정해 알려 주면 됩니다(메일 발송을 쓰지 않는 설정입니다).

## 3. 관리자 넘겨주기 (인수인계 체크리스트)

**받는 사람이 먼저 할 일**
1. 사이트에서 **가입**합니다(이름 필수).
2. 현재 관리자가 `admin.html` → **가입 승인**에서 승인합니다.
3. 현재 관리자가 **구성원** 탭에서 그 사람을 **관리자로 지정**합니다.

**현재 관리자가 할 일**
4. **관리자** 탭에서 자신을 **관리자 해제**합니다. (마지막 한 명은 해제되지 않게 막혀 있습니다. 반드시 다음 사람을 먼저 지정하세요.)
5. **GitHub 저장소 소유권 이전**: 저장소 → Settings → 맨 아래 *Transfer ownership*, 또는 Settings → Collaborators에서 새 관리자를 Admin으로 추가.
6. **Supabase 프로젝트 이전**: 대시보드 → Organization settings → Team에서 새 관리자를 **Owner**로 초대. 수락하면 이전 관리자는 나갑니다.
7. 이 문서의 "작성"과 연락처를 새 관리자 정보로 바꿉니다.

**비상: 관리자가 한 명도 없을 때** (예: 인수인계 전에 이전 관리자가 사라진 경우)
Supabase 프로젝트의 소유자가 대시보드 → SQL Editor에서 실행합니다. (이메일은 그 사람이 사이트에 가입한 주소)

```sql
insert into public.admins (user_id) select id from auth.users where email = '새관리자@이메일' on conflict do nothing;
update public.profiles set status = 'approved' where email = '새관리자@이메일';
```

## 4. 가게 정보 고치기·추가하기 (코드를 몰라도 가능)

가게 정보는 `data/restaurants.json` 한 파일입니다. 가게 하나는 이런 모양입니다.

```json
{
  "id": "2", "ko": "시딩", "zh": "喜鼎海胆水饺(星海湾壹号店)",
  "kind": "중식(모던)", "tags": ["중식"], "price": "100", "priceMin": 100, "region": "성해광장",
  "lat": 38.8756, "lon": 121.5827, "glat": 38.873, "glon": 121.5886,
  "menu": "성게 만두, 새우죽", "note": "대련에서 가장 유명한 맛집…",
  "photos": ["2-1.webp", "2-2.webp"], "nFood": 2
}
```

- **글만 고칠 때**: GitHub에서 `data/restaurants.json`을 열고 연필 아이콘으로 고친 뒤 Commit. 1~2분 뒤 사이트에 반영됩니다.
- **사진 추가**: 사진을 `photos/` 폴더에 올리고(긴 변 1200px 정도의 `.webp`/`.jpg` 권장, 위치정보(EXIF)가 없는 파일), 해당 가게의 `"photos"` 목록에 파일 이름을 추가합니다.
- `tags`는 사이트의 "종류" 필터에 쓰입니다(훠궈, 꼬치·구이, 해산물, 한식, 일식, 중식, 뷔페, 시장·마트, 술집·양식, 간식). `region`은 "지역" 필터에, `priceMin`(숫자)은 "가격" 필터에 쓰입니다.
- `lat`/`lon`은 폰 GPS(WGS-84)이고, `glat`/`glon`은 Amap 지도용 좌표(GCJ-02)입니다. **지도 마커는 `glat`/`glon`을 씁니다.** 좌표를 바꿀 때는 두 쌍 모두 맞춰야 합니다. Amap 좌표는 Amap에서 가게를 열어 주소 창의 좌표를 쓰면 됩니다.
- **승인된 제안을 영구 데이터로 옮기기**(선택): 제안은 Supabase에서 바로 사이트에 표시됩니다. 오래 보관하려면 `admin.html`의 백업을 받아 해당 내용을 위 형식으로 `restaurants.json`에 옮기세요.

## 5. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 사이트는 뜨는데 댓글만 안 보임, 가입 불가 | Supabase가 **일시 정지**되었을 수 있습니다(무료 프로젝트는 7일 접속 없으면 정지). 대시보드에서 *Restore project*. 이 저장소의 *keepalive* 작업이 일주일에 두 번 깨웁니다. GitHub이 60일 이상 변경이 없으면 이 작업을 끌 수 있으니 Actions 탭에서 다시 켜세요. |
| 사진이 안 보임 | 파일 이름 대소문자, `photos/` 폴더 경로, 파일이 올라갔는지 확인. |
| 지도 배경이 안 뜸 | 지도 타일은 Amap(高德)의 공개 타일입니다. 접속이 막히면 마커와 목록은 그대로 보입니다. 타일 주소는 `index.html`의 `L.tileLayer(...)` 한 줄입니다. |
| "승인 대기"가 계속 | 관리자가 승인해야 합니다. `admin.html` → 가입 승인. |
| 관리자가 `admin.html`에서 "관리자 권한이 없는 계정" | 3장의 비상 SQL을 Supabase 소유자가 실행. |
| 용량·한도 | 무료 플랜 한도(데이터베이스 500MB, 파일 1GB 등) 안에서 쓰고 있습니다. 대시보드 → Settings → Usage에서 확인. |

## 6. 보안과 키

- `config.js`의 `SUPABASE_ANON_KEY`는 **공개되어도 되는 키**입니다. 누가 무엇을 할 수 있는지는 Supabase의 규칙(RLS)이 정합니다. 규칙은 `supabase/schema.sql`에 있고, `supabase/rls_test.py`로 시험할 수 있습니다(46개 항목, 2026-10-23 전부 통과. 실제 관리자가 있으면 "마지막 관리자 해제 거부" 1개는 건너뜀).
- **`service_role` 키는 절대 저장소·채팅·메신저에 올리지 마세요.** 이 프로젝트는 그 키를 쓰지 않습니다.
- 이 저장소는 공개입니다(GitHub Pages 무료 사용 조건). 그래서 저장소에 개인정보·원본 사진·비밀번호를 넣지 마세요. 사진은 올리기 전에 위치정보(EXIF)를 지우고 줄여서 올립니다(사이트의 "새 가게 추천"은 자동으로 합니다).
- 사이트 주소를 아는 사람은 누구나 읽을 수 있습니다. 검색엔진에는 나오지 않게(noindex) 해 두었지만, 주소는 학교 선생님들에게만 공유하세요.

## 7. 처음부터 다시 만들기 (Supabase를 새로 만들어야 할 때)

1. supabase.com에서 새 프로젝트를 만듭니다.
2. Authentication → Providers → Email에서 **Confirm email**을 끄고 Save합니다(메일 발송 한도 문제를 피하려는 설정).
3. SQL Editor에 `supabase/schema.sql` 전체를 붙여 실행합니다.
4. Project Settings → API에서 *Project URL*과 *anon public* 키를 복사해 `config.js`에 붙입니다.
5. 사이트에서 가입한 뒤 3장의 SQL(비상 SQL)로 첫 관리자를 만듭니다.
6. (선택) `supabase/rls_test.py`로 규칙을 시험합니다. 사용법은 파일 맨 위 설명을 보세요. 시험 후 `delete from auth.users where email like 'rlstest-%@mailinator.com';` 로 시험 계정을 지웁니다.

## 8. GitHub Pages 올리기

1. 이 폴더의 내용을 새 GitHub 저장소(공개)에 올립니다.
2. 저장소 Settings → Pages → *Deploy from a branch* → `main` / `(root)` → Save.
3. 몇 분 뒤 `https://(계정).github.io/(저장소)/`에서 열립니다. 관리 화면은 같은 주소 뒤에 `/admin.html`입니다.

## 9. 알아 둘 점

- 지도 좌표 변환: 한국·일반 GPS는 WGS-84, 중국 지도(Amap)는 GCJ-02입니다. 섞으면 수백 m 어긋납니다.
- 대부분의 사진은 2024~2026년에 작성자가 직접 찍은 것입니다. 사람 얼굴이 나온 사진은 공개하지 않습니다. 학생·동료가 찍힌 사진을 발견하면 `photos/`에서 지우고 `restaurants.json`에서 파일 이름도 지워 주세요.
- 가격은 대략의 인당 가격(위안)이며 오래되었을 수 있습니다.
- 지도 타일은 Amap 공개 타일을 사용합니다. 대규모·상업적 사용은 Amap 약관에 맞지 않을 수 있으므로, 학교 안 자료로만 쓰세요.
